# Personal OpenNook Notch App

A native macOS utility with Calendar, Music, Focus Timer, and a reserved Home page. It uses OpenNook for the notch window, hover expansion, and animation. The idle notch stays at the screen-reported hardware width; Spotify playback enables artwork and animated bars beside it.

## Run the current version

Quit the previous copy, then from this project folder:

```sh
./Scripts/package-app.sh debug
open dist/OpenNookStarter.app
```

The debug bundle has been built and its signature verified. Use the bundled app for Calendar and Spotify permissions. `swift build` checks compilation; `swift run OpenNookStarter` is suitable for UI development but lacks the bundle's permission descriptions.

Requirements: macOS 15+, Swift 5.9+, and a compatible full Xcode toolchain. Earlier Command Line Tools failures are recorded in PROCESS.md. OpenNook is included locally, so no package download is needed.

## Calendar setup

1. Make sure your class calendar appears in Apple Calendar. A Google calendar under Other calendars may need enabling on [Google's sync selection page](https://www.google.com/calendar/syncselect).
2. In the notch's Calendar page, click **Connect Calendar**, approve macOS calendar access, and select the class calendar.
3. Select a date in the month to see that day's events. Month arrows load that month's events; Today returns to the current day.

The app only reads the selected calendar and saves its identifier locally. macOS calls the required permission full access, but this app has no event-writing operations. Event dates/times use the Mac's locale and time zone. Calendar changes, screen opening, and minute updates refresh EventKit data. Refresh does not force Google to sync; check Apple Calendar if classes are missing. If permission is denied, enable Calendars access in System Settings → Privacy & Security.

## Spotify setup and live mode

1. Open Spotify on this Mac and sign into your usual account.
2. Launch the bundled notch app, open Music, and click **Connect Spotify**.
3. Approve the macOS Automation request to control Spotify. Play a song in Spotify.

The app uses Spotify's installed scripting interface; it controls the account signed into that desktop app. It does not use Spotify Web API OAuth or control remote devices independently. Song data refreshes every two seconds after connection. Cover art loads from Spotify's HTTPS artwork URL. Animated bars indicate playing status; they are decorative and do not measure audio levels.

On the Music page, Spotify playback shows compact artwork and bars. On the Timer page, a running timer shows its compact countdown. Home and Calendar stay at quiet native width, as do paused/stopped sessions on their respective pages. The queue/source column has been removed so the current-track metadata and controls fill the space beside the artwork. Upcoming queue data is not displayed. If access fails, check System Settings → Privacy & Security → Automation, then reconnect. Connection preference is remembered; no Spotify password or OAuth token is stored.

## Focus timer

The timer uses a deadline, so elapsed time is accounted for while collapsed or asleep. +5 min extends either a running or paused timer. Enter minutes (`25`) or minutes:seconds (`25:30`), then press Return, Set, or Start. Applying a new duration resets the countdown; pause a running timer before editing. Values from one second through 24 hours are accepted. State survives tab changes and collapse but resets when the app quits. There is no completion sound, notification, or automatic break/session sequence in this version.

## Music spacing and adaptive playback bars

The music page uses a 124-point cover and a right-hand column constrained to that same 124-point height before the shared 90% scale (111.6 points rendered). Metadata, progress, and controls fit between the artwork’s top and bottom edges. The gap, side insets, and text/control groups are retained. All pages use the same 176.4-point rendered content height. Artwork is fetched once per URL change and reused for the expanded and live covers. A 16×16 CPU thumbnail sample derives an average tint; dark colors are brightened and grayscale/missing art gets a neutral tint for visibility. No extra library is required.

Playback bars interpolate independent pseudo-random targets with smooth transitions at up to 30 fps, rather than repeating a short wave. Tint changes blend over 0.6 seconds. Reduce Motion keeps them static. They still represent playback status, not real audio amplitude. Run `./Scripts/check-artwork-palette.sh` to check synthetic red/blue/grayscale/dark artwork. Real album matching and perceived smoothness need manual review.
